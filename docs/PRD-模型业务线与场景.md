文档版本：V1.5
需求编号：REQ-2026-09-001
适用角色：前端/后端/测试/AI原型
关联原型：无
上线周期：常规
更新记录：V1.5 业务线改为枚举提供（不建表），场景表挂业务线编码；V1.4 移除三方对接；V1.2 双列+一致性校验；V1.1 三级挂载；V1.0 初始版本

## 1. 需求背景与目标

### 1.1 业务背景

radar 以「模型」组织风控配置（字段/预处理/抽象/规则都挂在模型下），但模型目前只有自由文本的 MODEL_NAME/LABEL，看不出它服务哪条业务线、哪个风险场景。随着接入业务线增多（电商、本地生活、跑腿、社交、出行、大健康、元宇宙），运营在模型列表里无法按业务维度定位模型，页面事件报告也无法按业务线归因。

**业务线数据来源说明**：业务线本期不建表，由代码内枚举提供；后续公司基础服务统一供给业务线数据后替换（见 2.1）。因此本需求中「业务线」不可运营增删改，运营只维护场景。

### 1.2 需求目标

| 目标类型 | 目标描述 |
|:---------|:---------|
| 业务目标 | 100% 新建模型都挂到「业务线 → 场景」节点下，模型按树形结构组织 |
| 用户体验 | 列表页两次点击内定位到目标场景的模型；沿「业务线→场景→模型」的创建动线操作 |
| 运营目标 | 场景字典由运营自助维护，不依赖研发改代码 |

## 2. 领域定义：三级挂载结构

**结构**：业务线 → 场景 → 模型，严格三级。业务线来自枚举（固定列表），运营在业务线下建场景，最后在场景下建模型。例：电商（业务线）→ 营销防刷（场景）→ 登录防刷模型（模型）。

模型同时落 BUSINESS_LINE（业务线编码）和 SCENE_ID 两列：前者供业务线维度直接查询/统计（免 join），后者定义挂载位置。为防两者不一致，保存时由后端校验：所选场景必须属于所选业务线，否则拒绝保存。

### 2.1 业务线：枚举提供

| 项 | 说明 |
|---|---|
| 形态 | 代码枚举 `BusinessLineType`，每项含 code（小写中划线）、name（中文名） |
| 初始枚举 | ecommerce 电商、local-life 本地生活、errand 跑腿、social 社交、mobility 出行、healthcare 大健康、metaverse 元宇宙、unclassified 未分类 |
| 可维护性 | 本期运营不可增删改；新增业务线走研发发版 |
| 演进 | 后续公司基础服务统一提供业务线数据时，替换枚举数据源即可（接口不变），页面与模型数据不受影响 |

### 2.2 场景表

| 表 | 字段 | 说明 |
|---|---|---|
| engine_scene | ID, BUSINESS_LINE, NAME, CODE, STATUS, SORT, CREATE_TIME, UPDATE_TIME | 场景字典；BUSINESS_LINE 存业务线编码（varchar），逻辑关联枚举 |

遵循库内惯例：无物理外键。场景 CODE 全局唯一，格式 `小写中划线`（如 `marketing-anti-brush`）。

### 2.3 engine_model 增列

| 新增列 | 类型 | 约束 |
|---|---|---|
| BUSINESS_LINE | varchar(64) | 新建必填（业务线编码）；存量允许 NULL（显示在「未分类」节点下） |
| SCENE_ID | bigint | 新建必填；存量允许 NULL；保存时校验场景的 BUSINESS_LINE 与本列一致 |

### 2.4 初始场景数据（运营可改）

| 业务线 | 初始场景 |
|---|---|
| 电商 | 营销防刷、账户安全、支付反欺诈、商家刷单 |
| 本地生活 / 跑腿 / 社交 / 出行 / 大健康 / 元宇宙 | 各预置「账户安全」一条，其余运营自建 |
| 未分类 | 「待归类」；承接存量 5 个模板模型 |

## 3. 页面结构与入口

### 3.1 页面路由

| 路由路径 | 页面说明 |
|:---------|:---------|
| /modelList | 模型列表页（改造：左树右表） |
| /model/:id | 模型新建/编辑页（改造：归属场景字段） |
| /dimension | 场景管理页（新增：按业务线分组维护场景） |

### 3.2 /modelList 布局：左树右表

| 区域 | 内容 |
|------|------|
| 左侧树（约 1/4 宽） | 「全部模型」+ 业务线节点（展开出场景节点）。节点上显示模型数徽标；「未分类」固定置底。空状态引导：「还没有场景，去创建 →」跳 /dimension |
| 右侧表格 | 现有列（模型名/GUID/状态等）+ 新增「业务线 / 场景」列。默认展示「全部模型」；点击场景节点 → 只看该场景模型；点击业务线节点 → 看该业务线全部模型 |
| 表头「新建模型」按钮 | 点击弹出场景选择（级联：业务线→场景），选定后进入表单，归属场景带入 |

### 3.3 /model/:id 表单

| 区域 | 内容 |
|------|------|
| 字段区顶部 | 「归属场景」：级联选择器（业务线→场景）。从树节点/列表按钮进入时已锁定场景，可点「更换」重选。必填 |
| 其余字段 | 不变 |

### 3.4 /dimension 页面（场景管理）

| 区域 | 内容 |
|------|------|
| 左侧分组导航 | 业务线列表（来自枚举，固定，含场景数）；「未分类」置底 |
| 右侧场景列表 | 当前业务线下的场景：名称、CODE、模型数、状态开关、排序号、操作（编辑/删除）；头部「新增场景」，挂当前业务线 |

创建动线：左侧选业务线 → 新增场景 →（去 /modelList）在场景下新建模型。

## 4. 核心业务流程

### 4.1 创建动线（严格三级）

```
业务线为枚举固定项（不可建）
    ↓
/dimension 选业务线 → 新增场景（NAME 必填、CODE 全局唯一）
    ↓
/modelList 选场景节点（或直接点「新建模型」级联选择）
    ↓
模型表单「归属场景」已带入 → 填写其余字段保存 → BUSINESS_LINE + SCENE_ID 落库（后端校验场景属于该业务线）
```

### 4.2 场景维护

```
运营新增/编辑场景
    ↓
if NAME 为空或 CODE 重复:
    → 红框提示，不允许保存
if 删除场景:
    → 系统检查是否存在挂载模型
    → 有：Toast"该场景下有 N 个模型，不可删除"
    → 无：确认弹窗后删除
if 停用场景:
    → 已挂载模型不受影响（照常评估），仅新建模型时级联中不再出现
```

### 4.3 存量模型处理

上线时存量 5 个模板模型的 BUSINESS_LINE、SCENE_ID 置 NULL，归入「未分类 / 待归类」节点。运营在列表中逐个编辑迁移，不强制一次性补齐。

### 4.4 对评估链路的影响

无。业务线/场景仅用于管理侧组织与导航，engine 的 upload/getScore 接口、评估逻辑、事件入库（ES/Mongo）均不变。

## 5. 功能清单

### 5.1 API 变更

| 接口 | 变更 |
|---|---|
| GET /services/v1/dimension/tree | 新增：返回 业务线→场景 树（业务线来自枚举，含各节点模型数），供 /modelList 左树 |
| GET /services/v1/dimension/businessLine/list | 新增：业务线列表（枚举数据，前端下拉/分组用） |
| GET /services/v1/dimension/scene/list/{businessLine} | 新增：某业务线（编码）下场景 |
| PUT /services/v1/dimension/scene | 新增：场景保存 |
| DELETE /services/v1/dimension/scene | 新增：场景删除（查模型挂载校验） |
| GET /services/v1/model/list、POST /services/v1/model（query） | query 支持 businessLine（编码）/ sceneId 过滤；返回体增加 businessLineName、sceneName |
| PUT /services/v1/model | ModelVO 增加 businessLine、sceneId（保存时校验场景属于该业务线） |

业务线无保存/删除接口——枚举数据，维护走研发发版。

### 5.2 状态定义（场景）

| 状态 | Badge | 说明 | 行为影响 |
|------|-------|------|---------|
| 启用 | green | 正常使用 | 树中正常展示，新建模型可选 |
| 停用 | gray | 临时下线 | 树中灰显；新建模型级联不可选；已挂模型不受影响 |

业务线为枚举，无启用/停用状态。

## 6. 异常与边界场景

| 场景 | 触发条件 | 系统反馈 | 恢复方式 |
|------|---------|---------|---------|
| 删除有模型挂载的场景 | 挂载模型数 > 0 | Toast"该场景下有 N 个模型，不可删除" | 先迁移模型到其他场景再删 |
| 场景被停用后新建模型 | 级联选择中 | 该场景不可选 | 启用后可选 |
| CODE 重复 | 新增场景 CODE 已存在 | 字段红框"CODE 已存在" | 修改 CODE |
| 归属不一致 | 保存模型时 BUSINESS_LINE 与场景所属业务线不符（仅异常调用/旧数据可触发） | 返回"场景不属于该业务线"，拒绝保存 | 修正归属后重提 |
| 枚举调整 | 研发新增/下线业务线枚举值 | 下线的业务线下无场景时树中不显示；有场景时树中保留展示（模型不丢） | 场景随运营迁移 |
| 存量模型无归属 | BUSINESS_LINE 或 SCENE_ID 为 NULL | 显示在「未分类」节点下，维度列显示"—" | 编辑模型补选场景 |

## 7. 非功能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 场景/树查询响应 | ≤200ms | 场景数据量小，直接查库，不进引擎本地缓存；业务线读枚举，零开销 |
| 列表筛选 | ≤1秒 | model list 按 businessLine/sceneId 过滤无明显退化 |
| 存量迁移 | 上线时 5 个模板模型归入「未分类/待归类」 | SQL 脚本随版本发布 |

## 8. 验收标准

1. 给定业务线「电商」及场景「营销防刷」已存在，当在左树点击「营销防刷」节点并新建模型保存，则该模型出现在该节点下，列表维度列显示「电商 / 营销防刷」
2. 给定模型分属 3 条业务线，当左树点击业务线「电商」节点，则右侧仅显示电商业务线全部场景的模型
3. 给定场景「营销防刷」下挂有 1 个模型，当删除该场景，则 Toast 提示"该场景下有 1 个模型，不可删除"
4. 给定新建模型未选择归属场景，当点击保存，则归属场景红框提示"请选择归属场景"且不产生保存请求
5. 给定存量模板模型未配置归属，当打开模型列表，则其显示在「未分类」节点下，对它发起 engine 评估调用行为不变
6. 给定字典「跑腿-账户安全」为停用状态，当新建模型级联选择跑腿业务线，则场景项中不出现「账户安全」
7. 给定直接调用 API 保存模型时传入业务线「电商」+ 场景「跑腿-账户安全」（归属不符），当提交保存，则返回"场景不属于该业务线"且不落库
8. 给定 /dimension 页面，当打开业务线分组，则业务线列表不可增删改（无相关按钮），仅可维护其下场景

## 9. 名词统一字典

| 名词 | 定义说明 | 数据来源 |
|------|---------|---------|
| 业务线 | 顶层的业务归属维度，如电商、跑腿；本期枚举提供，后续基础服务供给 | BusinessLineType 枚举 |
| 场景 | 业务线下的风险场景，从属于业务线，如电商-营销防刷 | engine_scene 表（BUSINESS_LINE 存业务线编码） |
| 模型 | 一类风险事件的评估配置集合，同时挂业务线与场景 | engine_model 表（本需求增 BUSINESS_LINE、SCENE_ID） |
| 未分类 | 承接无归属存量模型的固定节点 | BUSINESS_LINE / SCENE_ID 为 NULL 的模型 |
